# 夜班工时与工资

班次属于shift_day；计划结束时间不大于开始时间时跨到次日。打卡是带偏移的时间，先存UTC，再用Asia/Shanghai拆分实际日历日。休息区间按夜班日期归属处理，先从实际工作区间扣除。单班最多18小时，打卡须为整分钟。缺IN或OUT整班隔离，不猜补卡。

按实际日历日判断法定假日、周末，法定假日优先3倍、周末2倍、工作日8小时内1倍、超过8小时1.5倍；正常分钟按同员工同日累计，跨班片段共享阈值。参数holidays可传日期列表，默认仅2026-10-01。金额按片段Decimal计算到分，paid为实发工资，差额为应发减实发。此规则用于样例计算，不替代当地劳动法规。

## 通用采信约定

CSV按UTF-8 BOM、UTF-8、GB18030回退，保留逻辑记录结束行号；引号内换行由CSV解析。重复表头单独计数，列数不齐隔离。编码与ID按字符串保形。缺失哨兵为 `-`、`N/A`、`NULL`、`未知` 与空串；不得作为零。数值先NFKC归一、去千分位，再用Decimal。日期采用ISO；时间必须带偏移并转UTC。空文件、全空行、仅表头分别返回EMPTY_FILE、BLANK_FILE、HEADER_ONLY。

重复键为(id,version)，完全相同行去重；同键内容冲突则整组隔离，不取最后一行。行数对账：输入=采纳+隔离+空行+重复表头+完全重复。运行幂等键由输入字节、参数与规则版本计算。

同一员工/归属日/方向的最高版本若有时刻、时薪、班次、休息或实发金额冲突，则整班隔离；选中IN与OUT的时薪、班次起止与休息起止也必须完全一致。

## 尾差裁决：先保留片段精度，再合成应付

片段是最小证据单元。`amount` 为片段参考落分额，仅用于展示；`exact_amount` 为片段精确额（Decimal，最多 10 位小数），倍率、分钟、费率变化只影响本片段，不因同批其他片段或批次补差被改写。

顺序固定为：

1. 按片段计算精确额，不落分。
2. 同员工全部片段精确额求和，**一次** `ROUND_HALF_UP` 到分，得到员工应付；差额记为员工层尾差（`residual`）。
3. 全批片段精确额总和**一次**落分，得到批次总额。
4. 批次总额与员工应付合计的差额，按最大余数法逐分归属到具名员工（`batch_adjustments`），优先抵消落分方向相反的员工余差，同值按员工编码排序。最终 `sum(员工最终应付) == 批次总额`。
5. 每条尾差都带 `piece`（片段ID：班次/开始时刻/分类）、来源行、原因文本；不把尾差分摊回片段金额。

同一员工同日多段倍率不同时，尾差只由该员工最后一条计薪片段（按开始时刻、片段ID排序）承载，因此归属稳定、可重放。页面（M5/M6）与导出（M7）按上述字段回查尾差归属与片段依据。

## 结算、付款与失效

- 保存批次只形成草稿，不切换当前结算；复核“通过”且 `reconcile.sealable`（行数对账平且 `payroll.settled`）才切换，并登记付款回执。
- `payroll.settled` 要求：最终应付合计等于批次总额、最大余数法归属完整、批次补差分数与差异分数一致。
- 同一批次重跑或重复复核复用同一付款回执（`payments.run_id` 主键），不重复付款。
- 规则版本（`RULE_VERSION`）、输入字节或参数变化会生成新批次；新批次复核通过后，旧批次标记 `superseded`，旧尾差 `residual_valid=false`，但原始行、片段、尾差与付款记录全部保留，旧尾差不再作为封存证据。
- 新批次复核退回、未结平或切换失败时，事务不提交，当前结算与旧付款记录保持原样。
- 导出仅在 `reconcile.sealable` 为真时开放；导出含运行清单、结算状态、对账、计算片段、员工应付、尾差、批次总额与隔离记录，校验和覆盖除结算状态外的证据行。
